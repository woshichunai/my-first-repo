# 给 Windows 本机 Codex 的执行任务

这是延续现有第二大脑项目的安装与验证任务。2026-11-04 已通过第一条本机测试闭环；先读 README、USER_GUIDE、BOUNDARIES 和 ROADMAP 核对现状，再执行尚未完成的项目，避免重装与重复配对。下列保留原始约束和验收要求。

## 已确定的约束

- 使用现有 Windows 电脑，用户表示可以持续开机并联网。
- 先验证再决定预算。本次不购买云服务器、不新增订阅、不充值或调用另计费的模型API。
- 优先 QQ 官方机器人 + AstrBot；普通QQ/NapCat路线尚未选择。
- AI优先测试用户现有官方Codex订阅登录；如果不可用，报告实际障碍，不偷偷改用收费API。
- iPhone通知选 Bark 做第一次实测。设备推送密钥仅在本机输入与保存。
- 目标是用户在QQ转发通知与课件后自动处理。不要将手动复制JSON作为最终方案。

## 0. 确认你运行在哪里

先确认执行环境确实是用户的Windows电脑。如果只有云端Linux环境，明确告知需要切换到本机执行会话，不要声称已在Windows安装。

仓库：https://github.com/woshichunai/my-first-repo
先读 projects/second-brain/QQ_ASSISTANT_PLAN.md 和 ROADMAP.md。
如果本机已经有仓库，先检查路径、git状态和远端；保留未提交改动，在隔离分支中工作。没有仓库才克隆到用户选择的项目目录。

私密数据和部署日志默认放在用户目录下 SecondBrain，或 %LOCALAPPDATA%/SecondBrain。不要提交课件、QQ标识、登录状态、Bark密钥、原始聊天或带令牌的日志。

## 1. 检查并准备最小环境

- 检查已有AstrBot、Codex客户端/CLI与必要运行时；复用已有安装，不遍历无关私人文件。
- 通过 codex login status 核实登录方式；不要打开或打印 auth.json。安装桌面App不代表CLI一定已就绪。
- 先确认用户使用ChatGPT订阅登录，再执行一次极小的合成文本测试。使用API-key模式时不要发起模型调用。
- 官方登录需要用户在自己的浏览器完成；不要要求其把密码、Cookie或凭据贴回聊天。
- AstrBot初次测试优先桌面版，官方页面：https://docs.astrbot.app/deploy/astrbot/desktop.html
- 已有可用版本就复用。没有安装时可使用 windows/setup-astrbot.ps1 下载、校验并启动官方v4.29.4安装界面；先检查脚本和系统架构。安装助手的下载/校验已在本机实测，但不能把安装包校验等同于 QQ 与手机配置完成。
- 保持管理界面只对本机可用。不设置端口转发、公开网址或额外管理员权限。
- 检查插电时睡眠设置并告知其对后台运行的影响；保留原值，避免无关系统修改。

## 2. 独立验证三条链路

### QQ 收件
- 按当前 AstrBot 官方文档添加 QQ 官方机器人，用户本人完成二维码绑定或平台授权。
- 仅绑定用户自己的私聊会话；官方机器人发送者可能是openid，不能假设等于QQ号码。通过本人发送测试消息核实。
- 验证普通文本、截图、PDF/PPTX、合并转发四类输入。
- 第一轮先使用固定回执验证消息链路，无需调用付费模型。
- 文件必须实际下载、检查文件名/大小并可再次取回；不能只看到消息标题就报告归档成功。
- 合并转发或文件接收若平台不支持，准确报告缺口。不能未经进一步选择就在主QQ上安装第三方桥接。
- 官方接口遇到开通/审核限制时记录实际错误，不假设已获得权限。

### 现有Codex处理
- 先使用以下合成样例验证提取，不创建真实提醒：
  文本：“测试数据：高数第三章作业，2026年11月6日22:00前提交。”
  期望结果：标题明确、截止时间2026-11-06T22:00:00+08:00、标注测试数据。
- 验证第二条“测试数据：周五晚上交作业”：不能凭空填写具体截止时刻，应返回待确认问题。
- 通过官方CLI/SDK的非交互方式集成前，查询实际版本支持的调用参数。不要从聊天网页抓取Cookie或转发登录令牌。
- 解析收件的运行环境应限制为只接收文本/文件内容并输出结构化结果；不给通知原文授予终端执行、凭据读取、给他人发消息的能力。
- 如当前CLI无法满足隔离与结构化输出要求，先保留为人工监督测试，不把未经约束的执行器挂到QQ上。
- 记录真实调用结果、耗时及失败原因；不要假设AstrBot原生支持Codex订阅接口。如需适配，编写最小插件并测试。
- 限额或网络失败时保留收件待处理，返回明确状态；已确认提醒不依赖模型继续运行。

### iPhone通知
- 用户在iPhone安装Bark并允许通知，在本机配置界面输入设备推送地址，不能写入公开仓库、聊天或命令日志。
- 使用项目官方接口说明：https://github.com/Finb/Bark
- 第一次测试只安排3次“第二大脑连接测试”通知，例如30秒、90秒、180秒；不得将测试内容当真实作业。
- 推送服务返回成功只代表已接受，不代表手机显示；请用户核对锁屏通知。
- 第二条后标记测试任务完成，验证第三条被取消。可以先用本地操作验证，QQ控制接通后再端到端验证。
- 每次短测试等待期间继续说明进度，不连续阻塞长时间。
- 另测手机不打开ChatGPT、使用日常网络时的通知到达。不要承诺任何网络下都100%到达。

## 3. 只接通第一条闭环

收件 → 保存来源 → 自动提取 → 回执必要疑问 → 创建持久化任务 → 手机通知 → 完成后取消提醒。

课件存放为私密目录中的 学科/章节/内部文件ID，保留原始文件名与来源元数据；章节不明放待分类，重复内容去重。只处理明确支持的类型，设置大小上限与安全文件名。图像和扫描PDF的OCR属于单独能力，失败时说明。

提醒时间用带时区时间戳，Asia/Shanghai。完成与延期必须取消旧计划。重启恢复已有队列；补发时合并遗漏，避免集中重复弹窗。最终截止任务策略待用户选定，不将示例3天/1天/2小时默认为已授权全局策略。

日程安排和手机看板在第一条闭环完成后继续做；此阶段不生成虚构课表或声称静态示意图已上线。

## 4. 交付证据与交接

在私密部署目录保存 SETUP_STATUS.md，分别记录：
- 已安装 / 尚未安装；
- QQ文本 / 截图 / 文件 / 合并转发是否真实验证；
- 模型使用何种登录方式、合成样例是否通过；
- 推送服务是否接受、手机是否由用户确认收到；
- 完成取消、重启恢复是否实测；
- 下一项阻塞及唯一必要用户操作。

对用户用简短中文报告结果，未通过的明确标出。需要扫码、手机权限、安装程序交互或新增费用时说明具体步骤；其他已授权可逆操作继续推进。
