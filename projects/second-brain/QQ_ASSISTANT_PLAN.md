# QQ 私人助理：需求与落地方案

更新：2026-11-03。状态：需求与技术路线已核查，QQ 接入、推送、文件自动归档和排程尚未部署。

## 目标体验

在 QQ 私聊里转发通知和课件，助理自动整理、返回结果、提前多次提醒，并在手机上显示可执行的日程。
用户日常只需转发、补充必要信息，以及用自然语言报告完成或变更。手动复制 JSON 不作为正式使用流程。

## 功能与完成标准

| 功能 | 处理规则 | 完成标准 |
| --- | --- | --- |
| QQ 收件 | 只处理授权用户的私聊；支持文本、图片、文件，合并转发需逐项实测 | 转发一条通知和一份课件后有收件回执，不能只看连接日志 |
| 提取任务 | 保留原文、来源和原始时间；分别存截止日期、具体时间、时区、可信程度 | “周五晚上交”缺具体时刻时追问，不擅自变成23:59 |
| 多次提醒 | 可建议截止前3天、1天、2小时；默认策略待用户选择，正式启用后按任务存为持久化计划 | 手机锁屏且不打开聊天时收到测试推送；重启后计划保留 |
| 课件归档 | 私密目录按学科/章节存放；优先参考文件名、封面、目录、正文 | 原件可取回、重复文件去重，不确定章节进入“待分类” |
| 安排时间 | 固定课程与约定先锁定，再按截止时间、预计耗时、可用时间排学习块 | 排程不冲突；安排不下时明确提示，不能挤占睡眠或假装可完成 |
| 手机可视化 | 目标为今日/本周日程、截止时间和课件目录；初期可用日历订阅，交互看板后续实现 | 手机可打开；修改在允许的刷新延迟内更新；不把静态预览当已上线 |
| 状态反馈 | “完成了”“延期到周六”“今晚有事”更新对应任务 | 更新后取消旧提醒、生成新提醒，日历不重复堆积 |

上述时间与演示任务均为规则示例，不代表已经创建任何用户提醒。

## 技术路线

1. QQ 入口优先验证腾讯官方机器人，通过 AstrBot 接入。它是机器人会话，不保证和普通 QQ 好友的所有功能一致。
2. 必须拿真实的私聊文本、截图、PDF/PPTX、合并转发分别验证。文件不支持时先报告缺口，不能声称所有格式可接收。
3. 如必须使用普通好友账号且官方入口无法满足，再评估备用 QQ + NapCat。NapCat 属于第三方非官方桥接，有账号风控及掉线风险；选定此路线前需要用户理解这一点，不默认接管主号。
4. AstrBot 负责消息入口和会话；任务、文件和通知记录保存到私密持久化存储。稳定提醒使用独立调度器，不要求大模型每次临时记住何时提醒。
5. iPhone 推送候选为 Bark（APNs）。QQ 用作交互入口，关键截止提醒不依赖 QQ 官方主动消息。原生弹窗受通知权限、专注模式、网络影响；上线必须做手机锁屏实测。
6. 手机日程初期可通过私密日历订阅展示，存在客户端刷新延迟。需要立即改计划或勾选完成时，用 QQ 指令或后续受保护的看板，不承诺订阅日历双向实时写回。
7. 模型优先验证现有官方 Codex 登录在个人可信设备上的非交互处理能力，以便利用已有订阅的 Codex 权益。这是待实现的适配，不是 AstrBot 原生开箱即用。登录状态、限额和网络均需实测。
8. 若选择模型 API，则使用单独配置的密钥、预算和计费；不要把 ChatGPT 余下的对话额度直接视为通用 API 余额。不要复制浏览器 Cookie、将登录凭据上传仓库，或以公共服务形式暴露个人 Codex 执行器。
9. 所有 AI 处理暂时不可用时，已确认任务的提醒仍应按数据库记录发送；新的未解析收件进入待处理，不捏造处理成功。

## 数据与可靠性

- 统一时区 Asia/Shanghai；保存带时区的时间戳。转发旧通知的“明天”不能按当前日期自动解释。
- 明确区分“原文已收到”“文件已下载”“任务已确认”“提醒已排入队列”“推送服务已接受”“手机实测收到”。
- 同一来源消息、相同文件内容去重；重发通知时识别更新，保留修改历史。
- 提醒包含任务、截止时间、最小下一步。完成任务后取消未发提醒；延期后取消旧计划再生成新计划。
- 重启后恢复队列；离线恢复时合并遗漏提醒，避免连续轰炸。外部推送无法绝对保证一次送达，重试必须有记录。
- 文件下载有大小限制与类型校验，存储名使用内部ID，原始文件名只是元数据。正文作为资料解析，不执行附件程序。
- 通知文本和课件属于待分析内容，不能让其中的指令改变管理员、泄露文件、执行命令或给他人发送消息。
- 保存原件与分类索引；“章节识别失败”和“下载失败”都需要可见状态与重试入口。
- 私密数据、课件、QQ标识、密钥、推送地址、订阅地址不进入公开仓库。代码仓库仅存程序和脱敏说明。

## 执行顺序

### 第一次闭环
- 确定运行位置：可持续开机的电脑，或用户选择的小服务器。
- 登录 QQ 接口并仅绑定用户本人；确认消息与课件能收到。
- 接通一条模型处理路径和 Bark 测试推送。
- 用一条测试任务验证两次短间隔提醒、完成后取消第三次提醒。
- 归档一份测试课件并通过 QQ 找回。
- 以上均成功后才标记“QQ助理基础闭环已跑通”。

### 第二阶段
- 导入课表、可用时间、作息与偏好，生成第一周安排。
- 手机查看日历，测试“今晚没空”后的重排与提醒变更。
- 再处理大课件、OCR、自然语言检索、备份恢复等实际需求。

## 需要的最少信息

- 是否有能稳定联网、持续开机的设备。
- 愿意承担的每月新增预算；这是成本约束，不是付费授权。
- 官方机器人体验能否满足文件转发；若不满足，再讨论备用账号路线。
- 排程阶段再收集课表、作息和任务耗时，不要求一开始填长表。
